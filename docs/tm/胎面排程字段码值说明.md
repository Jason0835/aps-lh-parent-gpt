# 胎面排程字段码值说明

本文档用于统一胎面排程重构中各业务表的字段码值口径，约束数据库存储、接口传输、前端展示、日志追溯、MES 发布回执保持一致。

## 使用原则
- 数据库字段统一存储稳定码值，不直接存中文展示值。
- 接口返回建议同时提供“码值”和“中文名称”，避免前端重复硬编码翻译。
- 同一类业务语义在不同表、不同服务中必须使用同一套码值。
- `is_delete` 统一采用：`0` 否，`1` 是，表示是否逻辑删除。
- `batch_no` 统一表示一次自动排程生成的批次号，用于关联任务与当前解释信息；同一天重排后旧批次默认删除。
- `enable_status` 统一使用字典 `biz_yes_no`：`0` 否，`1` 是，表示是否启用。

## 二、基础资料相关码值

### 1. 是否启用 `enable_status`

`enable_status` 使用项目通用字典 `biz_yes_no`。

| 码值 | 中文说明 | 适用表 | 业务含义 |
| --- | --- | --- | --- |
| `0` | 否 | `T_TM_PARAMS`、`T_TM_GLUE_MACHINE_REAL`、`T_TM_LOSS_SETTING`、`T_TM_SPECIFY_MACHINE` | 停用，不参与自动排程读取 |
| `1` | 是 | `T_TM_PARAMS`、`T_TM_GLUE_MACHINE_REAL`、`T_TM_LOSS_SETTING`、`T_TM_SPECIFY_MACHINE` | 启用，参与自动排程读取 |

自动排程读取可用规则时统一条件：

```sql
is_delete = 0
AND enable_status = '1'
```

## 四、参数编码建议

工装数量、补卷数量、最小起排量、取整规则等不扩展到 `T_TM_CURL_ROLL`，统一通过 `T_TM_PARAMS` 维护。

| 参数编码 | 中文说明 | 建议参数分组 |
| --- | --- | --- |
| `TM_MIN_START_QTY` | 最小起排量 | `GLOBAL` 或 `TREAD` |
| `TM_TOOL_TOTAL_QTY` | 工装数量或工装总量 | `GLOBAL` 或 `TREAD` |
| `TM_ADD_ROLL_QTY` | 补卷数量 | `GLOBAL` 或 `TREAD` |
| `TM_TAIL_ROUND_RULE` | 收尾取整规则 | `GLOBAL` 或 `TREAD` |
| `TM_NORMAL_ROUND_RULE` | 常规取整规则 | `GLOBAL` 或 `TREAD` |
| `TM_LARGE_SMALL_THRESHOLD` | 大小批量阈值 | `GLOBAL` 或 `TREAD` |
| `TM_STOCK_GUARD_SHIFT_COUNT` | 库存保障班次数 | `GLOBAL` |
| `TM_ROLLING_SHIFT_COUNT` | 局部滚动重算班次数 | `GLOBAL` |

## 六、班次表使用说明

### 1. 班次字典

用途：

- 维护稳定班次码值和中文展示名称。
- 推荐码值按六班模型扩展，例如 `CLASS1` ~ `CLASS6`。
- 字典只负责展示和基础码值，不负责具体日期的实际开班时间。

### 2. `T_TM_SHIFT_CONFIG`（班制配置）

用途：

- 维护具体工厂的班次配置。
- 支持节假日停班、临时加班、检修停班。
- 为自动排程提供"当日是否开班、具体时间段"依据。
- 作为唯一班次业务表承载计划开始时间、计划结束时间和开班状态。

关键规则：

- 同一工厂、同一班次编码、同一顺序只能存在一条未删除记录，唯一约束：`uk_tm_shift_config_factory_shift(factory_code, shift_code, shift_order, is_delete)`。
- 若 `open_flag = '0'`，自动排程不可在该班生成任务。
- 六班横向模型中班次时间窗由 `T_TM_SHIFT_CONFIG` 统一管理，`T_TM_SCHEDULE_RESULT` 不再冗余存储班次起止时间，前端展示时按 `factory_code + shift_code + shift_order` 关联配置获取。
- `plan_start_time` 和 `plan_end_time` 为 `varchar(8)` 类型，格式 `HH:mm:ss`，表示时间窗的时分秒。
- 若需要默认班制数据，可通过初始化脚本或维护功能提前生成 `T_TM_SHIFT_CONFIG`，不在运行时依赖字典推算。

## 七、开发落地建议

- Java 侧建议统一定义业务枚举，例如 `TaskStatusEnum`、`ShiftCodeEnum`、`AssignStatusEnum`。
- 前端页面不要自行硬编码中文展示，优先读取后端返回的中文名称。
- 导入、导出、MES 回执、事件日志都应复用本说明中的标准码值。
- 如后续码值扩展频繁，可再补一套通用字典表统一维护。
