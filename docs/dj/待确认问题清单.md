## 二、逻辑模糊点（影响算法正确性）

### 5. `MID_CAPACITY` / `NIGHT_CAPACITY` 已确认为无用参数并移除

| 字段 | 内容 |
|:---|:-----|
| 位置 | 参数表（`MID_CAPACITY=344`、`NIGHT_CAPACITY=252`），以及产能计算公式 |
| 问题 | 参数表中定义了两个定额参数，但公式说机台产能基线 = `DjMachineInfo.quata`。全局定额何时使用？是否作为机台未配置定额时的兜底值？缺少 `EARLY_CAPACITY`（早班定额），是否意味着早班 = 中班定额？中文"中班"对应的实质是夜班时间段的定额，容易产生混淆。 |
| 建议 | 确认为无用参数，已从设计文档参数表中移除。机台产能基线统一使用 `DjMachineInfo.quata`。 |
| **状态** | ✅ 已归档 |

### 6. `classShift` 与 `openMachineClass` 冗余

| 字段     | 内容                                                                                                                               |
| :----- | :------------------------------------------------------------------------------------------------------------------------------- |
| 位置     | 机台可用班次判定                                                                                                                         |
| 问题     | `classShift` 存中文"三班制/两班制"，`openMachineClass` 存 `"1,2,3"` 格式。机台可用班次判定只用 `openMachineClass` 即可，`classShift` 是否多余？如不多余，两者不一致时以哪个为准？ |
| 结论     | 班制和班次由垫胶机台管理功能进行统一，`classShift` 需要保留，后续可能扩展两班制场景。                                                                                   |
| **状态** | ✅ 已归档                                                                                                                           |

### 7. 损耗率计算时机问题

| 字段     | 内容                                                                    |
| :----- | :-------------------------------------------------------------------- |
| 位置     | 3.3 节（净需求计算）vs 5.5 节（排产后损耗率处理）                                        |
| 问题     | 5.5 节在排产完成后才将损耗率乘到计划量上。但净需求 = 总需求 - 库存，如果总需求不含损耗则净需求偏小，排产会导致最终实际产量不足。 |
| 结论     | 损耗率计算提前，临近收尾的规格要根据损耗率算出正确的需求量。                                                  |
| **状态** | ✅ 已归档                                                                |
