# 设计地图

## 核心目标
- 支持垫胶排程结果插单
- 支持垫胶排程结果调整（含调量、转机台）
- 支持垫胶排程结果删除
- 支持垫胶排程结果发布
- 支持垫胶排程结果导入

### 时间背景
- 每天班次顺序：**夜班 → 早班 → 中班**，每个班8小时
  - **夜班**：上一天 22:00 ~ 当天 06:00
  - **早班**：当天 06:00 ~ 14:00
  - **中班**：当天 14:00 ~ 22:00
- 垫胶排程结果以**排产日**为单位，每个排产日包含6个班次（2个完整的班次周期），排产日对应 T_DJ_SCHEDULE_RESULT 表中的 SCHEDULE_DATE 字段
- 垫胶排程结果表通过 `SCHEDULE_SHIFT_CLASS` 字段标识排程首班班次，默认中班（"03"）：
  - 首班=中班（"03"）：class1=中班, class2=夜班, class3=早班, class4=中班, class5=夜班, class6=早班
  - 首班=夜班（"01"）：class1=夜班, class2=早班, class3=中班, class4=夜班, class5=早班, class6=中班
  - 首班=早班（"02"）：class1=早班, class2=中班, class3=夜班, class4=早班, class5=中班, class6=夜班

### 业务规则
- **插单**：添加指定规格、机台、计划量、生产班次、生产次序的垫胶排程结果到排产日中
  - **约束一**：插单指定的班次、生产顺位不能早于该机台已经开始生产的规格。
  - **约束二（三档产能校验）**：产能校验分三档判断插单/调整量是否可执行。
    1. **第一档（定额内，直接执行）**：插单量 ≤ 剩余产能（机台定额 - 当班已有计划量）。插单后总量在定额内，无产能问题，直接执行插单操作。
    2. **第二档（超定额但未超实际剩余产能，提示确认）**：剩余产能 < 插单量 ≤ 实际剩余产能（机台定额 - 当前班次已生产量）。插单后总量超出定额，但考虑到该班次已生产部分产品，实际剩余产能仍有富余。需向用户提示坚持执行将导致哪些规格延后，用户确认后可执行。
    3. **第三档（超实际剩余产能，拒绝）**：插单量 > 实际剩余产能。插单量已超出当班实际剩余产能，直接提示用户超当班剩余产能，不能插单。
  - **约束三**：用户确认坚持执行插单后，按以下流程处理：
    1. 将新规格插入指定班次的指定顺位。
    2. 原顺位及之后的规格依次向后顺延一位。
    3. 顺延后若超出当班产能，则将超出的规格（从该班次末端顺位开始）顺延到下一个班次的最末顺位。
    4. 若顺延至下一个班次后仍然超出该班产能，则继续顺延至更下一个班次，依此类推。

- **调整**：根据用户输入的调整参数，调整垫胶排程结果（如调整计划量等涉及产能变动的操作）
  - 调整增量时，适用与插单相同的约束规则（约束一、二、三）。
  - **约束四**：若调整的规格已经在生产中，则减量后的计划量不能低于已生产量。

- **删除**：删除指定的垫胶排程结果
  - **约束**：只能删除从未发布过的记录（即通过发布记录识别是否曾发布过，曾有发布记录的不允许删除）。

- **发布**：将垫胶排程结果发布到MES系统中
  - **发布状态流转**：
    1. 自动生成或插单生成的计划，发布状态默认为**未发布**（releaseStatus="0"）。
    2. 发布成功后，状态更新为**发布成功**（releaseStatus="1"），并记录发布记录到 T_SCHEDULE_PUBLISH_RECORD。
    3. 发布失败后，状态更新为**发布失败**（releaseStatus="2"），发布失败的记录可以重新发布。
    4. 已发布成功的计划经过调整（插单、修改等）后，状态更新为**待发布**（releaseStatus="5"），待发布的计划可以重新发布。
  - **删除约束**：删除功能只能删除从未发布过的记录（即通过发布记录识别是否曾发布过，曾有发布记录的不允许删除）。

- **导入**：前端通过excel文件导入垫胶排程结果
  - 导入记录通过**工单号**识别唯一。
  - 工单号能关联上系统内已有排产记录的，限制条件与**调整**一致（适用约束一、二、三、四）。
  - 工单号为空或工单号在系统内不存在的记录，限制条件与**插单**一致（适用约束一、二、三）。

## 发布状态流转图

```
                        ┌─────────────┐
                        │   未发布(0)   │ ◄──── 自动生成 / 插单 / 导入新增
                        └──────┬──────┘
                               │ 发布
                               ▼
                     ┌─────────────────┐
           ┌────────►│   发布中(3)       │
           │         └──┬──────────┬───┘
           │            │ 成功     │ 失败
           │            ▼          ▼
           │    ┌────────────┐ ┌──────────┐
           │    │ 发布成功(1)  │ │ 发布失败(2) │
           │    └──────┬─────┘ └─────┬────┘
           │           │             │ 重新发布
           │   调整/插单/修改        │
           │           ▼             │
           │    ┌────────────┐       │
           │    │  待发布(5)   │◄─────┘
           │    └──────┬─────┘
           │           │ 重新发布
           └───────────┘
```

## 功能说明

### 1. 公共数据预加载

每次调整操作（插单/调整/删除/发布/导入）执行前，需先加载以下基础数据：

- **1.1**：加载垫胶机台数据
  - 数据源：`DjMachineInfo`
  - 表名：`T_DJ_MACHINE_INFO`
  - 加载条件：`factoryCode = 当前工厂`, `status = 0`（启用状态）
  - 用于：校验机台有效性、获取机台定额（QUATA，米/班）

- **1.2**：加载排程结果数据
  - 数据源：`DjScheduleResult`
  - 表名：`T_DJ_SCHEDULE_RESULT`
  - 加载条件：`scheduleDate = 当前排产日`, `factoryCode = 当前工厂`
  - 按 `machineCode` + 班次(`class{N}_sequence`) 排序

- **1.3**：加载定点机台数据
  - 数据源：`DjSpecifyMachine`
  - 表名：`T_DJ_SPECIFY_MACHINE`
  - 加载条件：`factoryCode = 当前工厂`
  - 用于：校验规格与机台的匹配关系

- **1.4**：加载发布记录
  - 数据源：`SchedulePublishRecord`
  - 表名：`T_SCHEDULE_PUBLISH_RECORD`
  - 加载条件：`procedureCode = "14"`, `scheduleDate = 当前排产日`
  - 用于：判断记录是否曾发布过

- **1.5**：校验排产日是否已被锁定（发布中/超时失败）
  - 如果排产日存在状态为"发布中"（"3"）或"超时失败"（"4"）的记录，禁止执行任何调整操作

- **1.6**：获取分布式锁 — 防并发冲突
  - 插单/调整/删除/发布等写操作涉及排程数据的变更，需防止集群环境下两个用户同时对同一机台操作导致数据错乱
  - **乐观锁方案**：在 `T_DJ_SCHEDULE_RESULT` 表增加 `VERSION` 字段（int），每次更新时 `version = version + 1`，更新条件为 `version = 读取时的旧版本号`
    - 更新 SQL：`UPDATE T_DJ_SCHEDULE_RESULT SET ... , VERSION = VERSION + 1 WHERE ID = ? AND VERSION = ?`
    - 若更新影响行数为 0，说明数据已被其他事务修改，抛出并发冲突异常，提示前端重试
  - **分布式锁保护**：使用 `@DistributedLock` 注解进行互斥
    - **插单、调量、转机台**：按分厂+日期+涉及的机台加锁
      - 锁 Key：`"APS:DJ:SCHEDULE:OPER_LOCK:" + factoryCode + ":" + scheduleDate + ":" + machineCode`
    - **删除**：按分厂+日期+所有待删除记录涉及的机台逐个加锁（若有多个机台，按机台编码排序后依次获取锁）
      - 锁 Key：`"APS:DJ:SCHEDULE:OPER_LOCK:" + factoryCode + ":" + scheduleDate + ":" + machineCode`
    - **发布**：按分厂+日期加锁（覆盖该排产日下所有机台，与自动排程互斥）
      - 锁 Key：`"APS:DJ:SCHEDULE:AUTO_LOCK:" + factoryCode + ":" + scheduleDate`
  - 锁获取失败时提示前端：当前排产日正在操作中，请稍后重试

### 2. 插单

#### 2.1 前端入参校验
- 入参：
  - `scheduleDate`：排产日期（必填）
  - `machineCode`：机台编码（必填）
  - `paddingCode`：垫胶编码（必填）
  - `class{N}_planQty`：指定班次计划量（必填，需大于0）
  - `class{N}_sequence`：指定班次生产顺位（必填，从1开始）
  - `factoryCode`：工厂编码

#### 2.2 约束一校验 — 生产顺位合法性
- 查询当前机台已开始生产的规格，数据来源：`T_DJ_DAY_FINISH_QTY`（垫胶排程计划每日各班完成量表），通过 `FACTORY_CODE` + `ORDER_NO` 关联，获取各班次完成量（`NIGHT_FINISH_QTY`=夜班, `DAY_FINISH_QTY`=早班, `MID_FINISH_QTY`=中班）
- 根据排产日的 `SCHEDULE_SHIFT_CLASS` 映射关系，将实际的夜班/早班/中班完成量对应到 class1~class6 的班次位置
- **判定**：若某规格在目标班次或更早班次有完成量 > 0，则视为已开始生产
- **校验**：插单指定的班次和顺位不能早于该机台已经开始生产的规格所在的班次和顺位
  - 如果已生产规格在 classN，顺位为 M，则插单顺位必须 > M 且班次不能早于 classN
  - 不通过则返回前端提示

#### 2.3 约束二校验 — 产能校验
- 获取机台定额（`DjMachineInfo.quata`，米/班）
- 计算指定班次已有排程的计划量总和
- 计算插单量加入后的总计划量
- **校验**：`该班次已有计划量 + 插单计划量 ≤ 机台定额`（同一班次内多个规格的总和不超过当班产能）
- 若超出产能，计算溢出量并识别该班次末端顺位的规格，返回前端提示：坚持插单将导致以下规格当班无法完成生产：[规格A、规格B……]
- 前端弹窗让用户确认是否坚持执行

#### 2.4 约束三 — 插入与顺延处理
- 用户确认坚持执行后，按以下步骤处理：

##### 2.4.1 插入新规格
- **根据垫胶编码加载施工表**：通过 `paddingCode` + `factoryCode` 查询 `T_MDM_CONSTRUCTION_INFO` 表，获取垫胶对应的施工信息
  - 填充 `glueCode`（垫胶胶料）= 施工表的 `PADDING_RUBBER`（垫胶胶料）
  - 填充 `paddingName`（垫胶物料名）= 施工表的 `PADDING_NAME`（垫胶物料名）
- **加载 T-1 日库存**：通过 `paddingCode`（物料编码） + `factoryCode` 查询 `T_DJ_STOCK` 表中排产日前一天（`STOCK_DATE = 排产日期 - 1`）的库存数据
  - 有效库存 = `STOCK_NUM`（库存量） + `MODIFY_NUM`（修正数量） - `BAD_NUM`（不良数量）
  - 填充 `stockQty`（有效库存量）
- **批次号、开产班次**：取当前排产日其他已有记录的 `batchNo` 和 `scheduleShiftClass` 值（同一排产日内所有记录这些字段值一致）
- **收尾标记**：默认 `"0"`（否）
- 创建新的 `DjScheduleResult` 记录
- 设置字段：
  - `dataSource = "1"`（插单）
  - `releaseStatus = "0"`（未发布）
  - `publishSuccessCount = 0`
  - `glueCode` = 从施工表加载的垫胶胶料
  - `stockQty` = T-1 日有效库存量
  - `batchNo` = 从已有记录获取的批次号
  - `scheduleShiftClass` = 从已有记录获取的开产班次
  - `tailFlag` = `"0"`（否，非收尾任务）
  - 指定班次的 `class{N}_planQty` = 插单计划量
  - 指定班次的 `class{N}_sequence` = 插单顺位
- **工单号生成规则**：
  - 工单号格式：批次号 + (本批次最大流水号 + 1)
  - 示例：`DJ20260626-DJ01-0001`
  - 自增序号：从 0001 开始，按该排产日内已有记录的最大序号 +1 生成

##### 2.4.2 原顺位及后续规格顺延
- 对指定班次中，原顺位 ≥ 插单顺位的所有规格，将其 `class{N}_sequence` 依次 +1
- 同时调整对应班次的排列顺序
- **记录原因分析**：每个发生顺位变动的规格，需在该班次的 `class{N}_analysis` 字段中记录：
  - 格式：`因[插单规格名称]插单推迟生产次序[原顺位]->[新顺位]`
  - 示例：规格A插单到顺位2，原顺位2的规格B顺延到顺位3 → `因规格A插单推迟生产次序2->3`
- 若后续步骤中该规格被顺延到其他班次，按2.4.3规则记录

##### 2.4.3 产能溢出检测与跨班顺延
- 重新计算该班次所有规格的总计划量
- 若总计划量 > 机台定额，则从该班次**末端顺位**开始，将超出部分顺延到**下一个班次的最末顺位**
- 被顺延的规格在下一个班次中，保持其原有的顺位相对顺序
- 若顺延至下一个班次后仍然超出该班产能，继续顺延至更下一个班次，依此类推
- **记录原因分析**：
  - **跨班顺延**：被顺延到下一个班次的规格，需在原班次和新班次的 `analysis` 字段中记录
    - 原班次 `class{N}_analysis`：`因[插单规格名称]插单，[本规格名称]推迟生产班次classN->classN+1`
    - 新班次 `class{N+1}_analysis`：`因[插单规格名称]插单，[本规格名称]从classN推迟至本班`
  - **同班次内顺位顺延**（因跨班顺延后腾出空位导致的重新排列）：按4.2规则记录
- **已到最后一个班次（class6）仍有溢出时**：不再跨排产日顺延，改为对末端顺位的规格进行**减量处理**
  - 从末端顺位开始，减少计划量直到符合产能上限
  - 在该班次的原因分析字段 `class{N}_analysis` 中记录：`因[插单规格名称]插单/调整减量n`（n 为实际减去的米数）
  - 若减量后该规格计划量 ≤ 0，则将该规格从该班次移除（`class{N}_planQty`、`class{N}_sequence` 置为 NULL）
- **跨班顺延数据清理规则**：
  - 规格从 classN 顺延到 classN+1 后，原 classN 的 `class{N}_planQty` 置为 NULL
  - 原 classN 的 `class{N}_sequence` 置为 NULL
  - 原 classN 的 `class{N}_analysis` 保留不变（原因分析不随计划量顺延）
  - 被顺延到 classN+1 的规格，其 `class{N+1}_planQty` 设置为原 classN 的计划量
  - 被顺延到 classN+1 的规格，其 `class{N+1}_sequence` 设置为该班次当前最大顺位 + 1

##### 2.4.4 跨班顺延算法伪代码
```
function 处理插单顺延(机台, 班次列表, 插单班次索引, 插单顺位, 插单规格名称):
    // 1. 插入新规格到指定位置
    插入规格(班次列表[插单班次索引], 插单顺位, 新规格)

    // 2. 顺延原顺位及后续规格，记录顺位变动原因
    for each 规格 in 班次列表[插单班次索引]:
        if 规格.顺位 >= 插单顺位:
            原顺位 = 规格.顺位
            规格.顺位 = 规格.顺位 + 1
            规格.原因分析 = 规格.原因分析 + ";因" + 插单规格名称 + "插单推迟生产次序" + 原顺位 + "->" + (原顺位 + 1)

    // 3. 从当前班次开始，逐班检查产能溢出
    for i = 插单班次索引 to 班次列表.length - 1:
        班次 = 班次列表[i]
        总计划量 = sum(班次.所有规格.计划量)
        溢出量 = 总计划量 - 机台定额

        if 溢出量 > 0:
            // 从末端顺位开始取出规格，顺延到下个班次
            待顺延规格列表 = []
            while 总计划量 > 机台定额 and 班次.规格列表不为空:
                末位规格 = 班次.规格列表.移除最后一个()
                待顺延规格列表.加入(末位规格)
                总计划量 = 总计划量 - 末位规格.计划量

            if i + 1 < 班次列表.length:
                // 放入下一个班次的最末顺位，记录跨班原因
                下一班次 = 班次列表[i + 1]
                for each 待顺延规格 in 待顺延规格列表.反转():
                    下一班次.规格列表.加入(待顺延规格)
                    待顺延规格.顺位 = 下一班次.规格列表.size()
                    // 原班次记录：因X插单，本规格推迟生产班次classN->classN+1
                    待顺延规格.班次[i].原因分析 = 待顺延规格.班次[i].原因分析 + ";因" + 插单规格名称 + "插单，该规格推迟生产班次class" + i + "->class" + (i + 1)
                    // 新班次记录：因X插单，本规格从classN推迟至本班
                    待顺延规格.班次[i + 1].原因分析 = "因" + 插单规格名称 + "插单，从class" + i + "推迟至本班"
            else:
                // 已到最后一个班次（class6），无法继续顺延
                // 对末端顺位的规格进行减量处理，直到符合产能上限
                while 总计划量 > 机台定额 and 班次.规格列表不为空:
                    末位规格 = 班次.规格列表.查看最后一个()
                    溢出量 = 总计划量 - 机台定额
                    if 末位规格.计划量 > 溢出量:
                        // 部分减量
                        减量 = 溢出量
                        末位规格.计划量 = 末位规格.计划量 - 减量
                        末位规格.原因分析 = 末位规格.原因分析 + ";因" + 插单规格名称 + "插单减量" + 减量
                        总计划量 = 机台定额
                    else:
                        // 整条规格移除
                        移除规格 = 班次.规格列表.移除最后一个()
                        移除规格.原因分析 = 移除规格.原因分析 + ";因" + 插单规格名称 + "插单减量" + 移除规格.计划量
                        移除规格.计划量 = NULL
                        移除规格.顺位 = NULL
                        总计划量 = sum(班次.所有规格.计划量)
```

#### 2.5 保存数据
- 插入新记录 + 更新被顺延的记录
- **事务要求**：整个2. 插单（校验 + 插入 + 顺延 + 保存）必须在同一个数据库事务中执行，任一环节失败则全部回滚
  - 使用 `@Transactional(rollbackFor = Exception.class)` 注解
  - 事务范围包括：2.2~2.5 的所有数据库写操作
- 记录操作日志到 `T_DJ_SCHEDULE_RESULT_LOG`
- 记录调度员操作日志到 `T_DJ_DISPATCHER_LOG`（操作类型：插单）

### 3. 调整

#### 3.1 调整类型判定
调整操作分为以下类型：

| 调整类型 | 说明 | 涉及字段 |
|---------|------|---------|
| 调量（增量） | 增加某规格在某班次的计划量 | class{N}_planQty |
| 调量（减量） | 减少某规格在某班次的计划量 | class{N}_planQty |
| 转机台 | 将规格转移到另一个机台 | machineCode |

#### 3.2 公共校验

##### 3.2.1 发布状态校验
- 查询要调整的记录 `releaseStatus`
- 若状态为"发布中"（"3"）或"超时失败"（"4"），拒绝操作

##### 3.2.2 生产中校验（约束四 — 减量限制）
- 若调整记录已开始生产（通过 MES 接口获取实际生产状态）
- **校验**：减量后的计划量 ≥ 已生产量
- 不通过则返回前端提示

#### 3.3 调量（增量）处理

增量按以下两种场景分别处理：

**场景一：目标规格在目标班次已有计划量（`class{N}_planQty` 不为 NULL）**
- 直接在该规格现有计划量的基础上累加，**不改变顺位**，相当于在该规格本班生产末尾追加产量
- 累加后重新校验该班次总计划量是否超出产能上限：
  - 若未超出，直接保存
  - 若超出，从该班次末端顺位开始触发顺延，参照2.4的处理逻辑
- 原因分析：在该班次的 `class{N}_analysis` 中追加 `因[本规格]调整追加量n`

**场景二：目标规格在目标班次没有计划量（`class{N}_planQty` 为 NULL）**
- 相当于新插单，走完整的插单逻辑（参照2.2~2.4）
- 原因分析规则与2.4.2/2.4.3一致，格式中将"插单"替换为"调整"
  - 同班次顺位滚动：`因[目标规格名称]调整推迟生产次序i->j`
  - 跨班顺延：`因[目标规格名称]调整，[本规格名称]推迟生产班次classN->classN+1`
  - 减量处理：`因[目标规格名称]调整减量n`

- **跨班次增量场景**：用户可能一次性对同一个规格的多个班次同时增加计划量
  - 处理策略：**逐班次独立处理**，按班次顺序（从早到晚）逐个应用增量逻辑
    - 先处理最早班次的增量，该班次顺延后可能导致规格顺延到下一班次
    - 再处理下一班次的增量时，需基于上一班次顺延后的最新状态进行计算
  - 示例：规格A在class1增量200米，同时class2增量100米
    - 第1步：class1 +200米，触发顺延，若溢出则将规格顺延到class2
    - 第2步：class2（已包含class1顺延过来的规格）+100米，重新校验产能

#### 3.4 调量（减量）处理
- 直接减少指定班次的计划量
- 若减量后计划量为0，则清空该班次数据：
  - 该班次的 `class{N}_planQty` 置为 NULL
  - 该班次的 `class{N}_sequence` 置为 NULL
  - 其他班次数据及记录本身保留，不删除整条记录
- **顺位空洞整理**：当班次内某个规格的计划量归零后，该班次剩余规格的顺位需要重新整理，确保顺位从1开始连续递增
  - 例如：清空前顺位为 [1, (清空), 3, 4] → 清空后整理为 [1, 2, 3]
- 不需要执行产能顺延（仅减量不会导致产能溢出）

#### 3.5 转机台处理
- 校验目标机台是否存在且启用
- 校验目标规格是否允许在该机台生产（通过定点机台表 `T_DJ_SPECIFY_MACHINE` 检查）
  - `JOB_TYPE = "0"`（限制作业）：允许
  - `JOB_TYPE = "1"`（不可作业）：不允许
- 校验目标机台在目标班次是否有开机（通过 `OPEN_MACHINE_CLASS` 字段）
- 校验通过后更新记录的 `machineCode`

#### 3.6 调整后状态更新
- 若调整前 `releaseStatus = "1"`（发布成功），调整后更新为 `releaseStatus = "5"`（待发布）
- 若调整前 `releaseStatus = "0"`（未发布）或 `"2"`（发布失败），保持不变
- **事务要求**：整个3. 调整（校验 + 调整 + 顺延 + 状态更新）必须在同一个数据库事务中执行
  - 使用 `@Transactional(rollbackFor = Exception.class)` 注解
  - 配合1.6 的乐观锁进行并发控制
- 记录操作日志

### 4. 删除

#### 4.1 删除前置校验
- **校验一**：查询记录 `publishSuccessCount`，如果 > 0，说明曾发布过，不允许删除
- **校验二**：通过 `T_SCHEDULE_PUBLISH_RECORD` 表查询，如果该排产日存在该记录的发布记录，不允许删除
- **校验三**：若记录状态为"发布中"（"3"）或"超时失败"（"4"），不允许删除

#### 4.2 执行删除
- 逻辑删除（设置 `IS_DELETE = "1"`）
- 批量删除时，逐条校验，任一不符合则跳过
- **事务要求**：批量删除时，所有成功的删除操作应在同一个事务中执行，部分失败时已成功的删除不回滚（逐条独立提交）
- 记录操作日志到 `T_DJ_DISPATCHER_LOG`（`OPER_TYPE = "3"`，操作类型：删除）

### 5. 发布

#### 5.1 发布前置校验
- **校验一**：查询选中的记录列表，过滤出 `releaseStatus` 为 "0"（未发布）、"2"（发布失败）、"5"（待发布）的记录
- **校验二**：对过滤后的记录获取分布式锁，防止集群环境下重复发布
- **校验三**：确认记录不是"发布中"（"3"）或"超时失败"（"4"）状态

#### 5.2 执行发布

##### 5.2.1 记录发布日志
- 创建 `SchedulePublishRecord` 记录
  - `procedureCode = "14"`
  - `scheduleDate = 当前排产日`
  - `publishStatus = "3"`（发布中）
  - `dataVersion = 数据版本号`

##### 5.2.2 同步数据到 MES
- 调用 `deployDjScheduleToMid` 将排程数据发布到中间库
- 同步内容：排程结果记录（机台、规格、计划量、顺位等）

##### 5.2.3 更新发布状态
- 发布成功后：
  - 更新 `releaseStatus = "1"`（发布成功）
  - `publishSuccessCount = publishSuccessCount + 1`
  - `newestPublishTime = 当前时间`
  - 更新发布记录状态为发布成功
- 发布失败后：
  - 更新 `releaseStatus = "2"`（发布失败）
  - 更新发布记录状态为发布失败
- **事务要求**：发布日志记录 + 同步 MES + 状态更新必须在同一事务中，任一失败则全部回滚
  - 使用 `@Transactional(rollbackFor = Exception.class)` 注解
  - 分布式锁应在事务开始前获取，事务提交后释放

### 6. 导入

#### 6.1 导入前置校验
- **校验一**：排产日期不能早于当前日期
- **校验二**：该排产日不能存在"发布中"或"超时失败"的记录
- **校验三**：该排产日不能已有发布成功的记录（`isPublish = true` 禁止导入）

#### 6.2 解析 Excel 文件
- 使用 `ExcelUtil<DjScheduleResult>` 解析导入文件
- 解析字段对照：

| Excel列 | 对应实体字段 |
|---------|------------|
| 工单号 | orderNo |
| 排程日期 | scheduleDate |
| 机台 | machineCode |
| 垫胶编码 | paddingCode |
| 垫胶物料名 | paddingName |
| 胶料代码 | glueCode |
| 口型板编码 | mouthPlateCode |
| 1~6班顺序 | class{N}_sequence |
| 1~6班计划量 | class{N}_planQty |

#### 6.3 导入数据处理
- 按工单号（`orderNo`）识别每条导入记录，匹配规则：**精确匹配 `ORDER_NO` 字段**
  - **工单号不为空且存在**（`T_DJ_SCHEDULE_RESULT` 表中存在 `ORDER_NO = 导入工单号` 的记录） → 视为调整操作，限制条件与调整一致（适用约束一、二、三、四）
    - 查询系统内已有记录，更新其计划量等字段
    - 若为增量，执行产能校验和顺延逻辑
    - 若为减量，校验不低于已生产量
  - **工单号为空或不存在** → 视为插单操作，限制条件与插单一致（适用约束一、二、三）
    - 创建新记录
    - `dataSource = "2"`（导入）
    - `releaseStatus = "0"`（未发布）
    - 工单号自动生成，规则同2.4.1
    - 执行顺位插入和产能顺延逻辑

#### 6.4 保存导入结果
- 批量保存导入记录
- 记录导入日志到 `T_IMPORT_LOG`
- 记录导入错误到 `T_IMPORT_ERROR_LOG`
- 返回导入结果（成功/失败条数）

## 机台产能计算规则

### 机台定额
- 每个机台有 `QUATA`（生产定额，单位：米/班）
- 一个班次内，同一机台所有规格的计划量总和不得超过该机台的当班定额
- 机台定额受班制影响：三班制可开3个班，两班制按 `OPEN_MACHINE_CLASS` 配置开机班次

### 班次产能计算公式
```
当班总计划量 = Σ(该班次所有规格的 class{N}_planQty)
产能利用率 = 当班总计划量 / 机台定额 × 100%
产能溢出 = 当班总计划量 > 机台定额
```

### 生产顺位规则
- 每个班次内，规格按 `class{N}_sequence` 升序排列生产顺位
- 顺位从1开始，连续递增
- 插单/调整后需重新整理顺位序号，确保连续
- 同一机台同一班次内各规格顺位不重复

## 前端交互说明

### 插单交互流程
1. 用户选择排产日、机台、班次
2. 系统加载当前班次已有排程列表（按顺位排序）
3. 用户选择插入顺位，输入规格、计划量
4. 前端调用 `validateAdd` 校验接口
5. 若校验通过，直接提交
6. 若产能不足（约束二触发），弹窗提示影响规格，用户选择：
   - 取消：放弃操作
   - 坚持执行：调用 `editSave` 提交，后端执行顺延逻辑

### 调整交互流程
1. 用户选中一条排程记录，选择调量或转机台
2. 输入调整参数
3. 前端校验：
   - 减量时不可低于已生产量（约束四）
   - 增量时参照插单校验流程
4. 提交到后端执行

### 发布交互流程
1. 用户选中要发布的排程记录（可多选）
2. 前端显示选中记录数和发布状态
3. 用户点击发布按钮
4. 后端同步到 MES 并更新状态
5. 前端刷新列表显示最新发布状态
