# 设计地图

## 核心目标
- 输入工厂与排产日期，自动根据成型计划排产垫胶工序6个班的备库计划

### 时间背景
- 每天班次顺序：**夜班 → 早班 → 中班**，每个班8小时
  - **夜班**：上一天 22:00 ~ 当天 06:00
  - **早班**：当天 06:00 ~ 14:00
  - **中班**：当天 14:00 ~ 22:00
- 成型计划生成：每天早上6点前生成从**早班（当天06:00）** 开始连续8个班的成型计划
- 垫胶排程触发：每天7点根据已生成的8个班成型计划，计算从**中班（当天14:00）** 之后连续6个班的垫胶备库计划

### 业务规则
- **提前生产**：垫胶计划原则上会提前成型一个班开始生产，确保成型生产时垫胶已备好。具体约束：垫胶生产出来后需要停放冷却3小时才可以送往成型工序使用，因此最晚生产时间 = 成型规格开始时间 - 3小时 - 生产时长
- **台车工装**：垫胶通过垫胶机台完成生产后，需使用台车工装进行卷曲收纳
  - 台车规格是固定的，但不同规格的垫胶在一个台车上可收纳的长度有差别
  - 排产时需根据垫胶规格查阅对应台车的容量（米/台车）
  - 台车数量是有限的，一个班各机台的总排产量之和不能超过工装总数所能承载的最大米数
  - 台车约束公式：`一个班总排产量 ≤ (工装总数 - (有效库存 / 卷曲米数) × 整车率) × 台车容量`
- **未收尾规格的排产约束**：对于成型规格尚未收尾的垫胶，生产量需为台车容量的整倍数，避免产生无法收纳的零头料
- **已收尾规格的精确排产**：对于成型规格已全部收尾的垫胶（即不再有后续成型需求），需按施工信息的单耗精确换算成需求米数，并乘以损耗率，不要求台车整倍数约束
- **放假停产处理**：
  - **停产不足2天**：垫胶工序需提前生产，在停产前备足成型开产班次所需的垫胶库存，确保成型开产后垫胶不断供
  - **停产超过2天**：垫胶工序按成型工序的需求量进行收尾，收尾计算规则与成型收尾一致（即精确换算需求米数，含损耗率）。原因是垫胶有保鲜期，超过2天存在超期风险，因此需在停产前收尾，避免产生过期废料
  - **开产策略**：停产超过2天后开产，开产时库存为0，当班生产需按以下策略执行：
    - 根据成型需求时间点，优先生产最早需求时间的规格
    - 当某规格库存达到安全水位线后，立即切换生产下一优先级的规格
    - 目标：确保成型工序能开动尽可能多的规格同时生产，不因缺料而等待
    - 在确保开产班次的所有需求规格库存均达到安全水位后，切换回正常排产模式
- **排产深度**：根据各垫胶规格对应的成型机台数量决定该规格的供应窗口班次数（即该垫胶需求计算时合计多少个班的成型计划量）。不同垫胶规格的成型机台数可能不同，排产深度也不同。
  - 某垫胶规格的成型机台数 = 消耗该垫胶的成型计划去重后的机台数量
  - 成型机台数越少，单机台产量负荷越大，该垫胶需覆盖更多成型班次；成型机台数越多，总产能越大，覆盖较少班次即可满足
  - 排产深度同时也决定了垫胶下计划的班次数：垫胶下计划班次数 = 排产深度 + 1（提前一个班）
  - 排产深度可根据实际情况调整
- **新规格准备料**：新规格（`isNewSpec=true`，即库存表中无该垫胶代码记录）准备料需提前2个班下计划
- **实验量试规格**：实验量试规格需提前3天下计划。判定依据为 `MdmConstructionInfo.productionStage`：`T`（量试阶段）或 `X`（试制阶段）视为实验/量试规格
- **规格上机优先级**：排产时按以下优先级顺序选择下一个生产的规格：
  1. 本班库存有缺口的优先
  2. 没有库存缺口，上一个班最后一个规格还有需求量则优先（规格续作）
  3. 与上一个规格胶料相同、口型相同的优先
  4. 与上一个规格胶料相同的优先
  5. 与上一个口型相同的优先
  6. 胶料组相同的优先
  7. 胶料序号升序
  8. 库消比（库存:成型消耗量）的比值升序
  9. 垫胶编码升序

## 功能结构
- 工程名称：aps-engine-dj

- 入口方法：autoDjSchedule
- 入口参数1：factoryCode 工厂
- 入口参数2：scheduleDate 排产日期

### 步骤1.5：数据校验
自动排程执行前，对关键数据进行完整性校验，校验不通过时抛出异常提示前端：
1. **成型排程结果校验**：步骤1加载的成型排程结果必须存在且不为空，否则提示"未加载到成型计划数据，自动排程无法执行"
2. **胎胚施工信息校验**：成型计划中有需求量的胎胚代码，必须能在施工表（T_MDM_CONSTRUCTION_INFO）中匹配到对应的施工记录。若有任意胎胚代码匹配不到施工数据，提示"未加载到施工数据，自动排程无法执行"；若所有胎胚代码均无对应的施工数据（constructionList为空），同样提示"未加载到施工数据，自动排程无法执行"
   - **施工数据有效性校验**：匹配到施工记录后，进一步校验每条施工记录的`PADDING_CODE`（垫胶代码）不能为空，且`PADDING_LENGTH`（垫胶长度/单耗）必须为大于0的有效数值。若有任意施工记录的垫胶代码或垫胶长度无效，提示"施工数据中垫胶代码或垫胶长度无效，自动排程无法执行"
3. **机台可用性校验**：步骤4.1加载的垫胶机台列表必须存在且不为空，否则提示"未加载到垫胶机台数据，自动排程无法执行"

> 数据校验贯穿整个排程流程，以上校验分别在步骤1、步骤2、步骤4.1对应阶段执行，确保排程基础数据完整后方可进入下一步。

### 步骤2：解析成型计划获取垫胶施工清单
- 2.1 加载施工数据
  - 数据源：com.zlt.aps.mdm.api.domain.entity.MdmConstructionInfo
  - 表名：T_MDM_CONSTRUCTION_INFO
  - 加载方式：使用 DjEngineConstructionInfoMapper（继承 CommBaseMapper`<MdmConstructionInfo>`）的 selectList 直接查询
  - 加载条件：factoryCode = factoryCode参数, constructionCode in (成型计划的胎胚代码列表)
  - 关键字段（实际使用字段）：

| 字段名 | 类型 | 备注 |
|--------|------|------|
| FACTORY_CODE | varchar | 工厂编号 |
| CONSTRUCTION_CODE | varchar | 施工号（与成型计划EMBRYO_CODE关联） |
| PADDING_CODE | varchar | 垫胶代码 |
| PADDING_LENGTH | decimal | 垫胶长度（单耗，用于将成型计划量换算为垫胶需求米数） |
| PRODUCTION_STAGE | varchar | 生产阶段：S-投产阶段、T-量试阶段、X-试制阶段 |
- 2.2 关联成型计划与施工数据获取垫胶信息
  - 关联条件：CxScheduleResult.embryoCode（胎胚代码） = MdmConstructionInfo.constructionCode（施工信息中的胎胚代码匹配）
  - 多版本处理：成型计划的每个班次有独立示方书编号（class{N}RecipeNo），施工数据有BOM版本（MdmConstructionInfo.constructionVersion），关联时需按班次匹配对应的BOM版本：
    - 1班（class1）→ class1RecipeNo = constructionVersion
    - 2班（class2）→ class2RecipeNo = constructionVersion
    - ...
    - N班（class{N}）→ class{N}RecipeNo = constructionVersion
  - 提取结果：每个班次成型计划所对应的垫胶代码（MdmConstructionInfo.paddingCode）

## 步骤3： 根据垫胶施工清单计算垫胶需求清单
- 3.1 加载库存数据
  - 数据源：com.zlt.aps.dj.api.domain.entity.DjStock
  - 表名：T_DJ_STOCK
  - 加载方式：使用 DjStockMapper.selectList
  - 加载条件：factoryCode = factoryCode参数, 取T-1日库存（早班量）, materialCode in (垫胶施工清单的垫胶代码集合)
  - 关键字段：

| 字段名 | 类型 | 备注 |
|--------|------|------|
| FACTORY_CODE | varchar | 工厂编码 |
| STOCK_DATE | datetime | 库存日期 |
| MATERIAL_CODE | varchar | 库存物料编号（垫胶代码） |
| STOCK_NUM | decimal(18,2) | 库存量 |
| MODIFY_NUM | decimal(18,2) | 修正数量 |
| BAD_NUM | decimal(18,2) | 不良数量 |
  - 有效库存量计算：stockNum + modifyNum - badNum
- 3.2 从垫胶施工清单获取成型需求量和单耗，按班次整理成型计划消耗量
  - 从步骤2的垫胶施工清单中获取每个垫胶代码的成型需求量（对应班次计划量）和单耗（MdmConstructionInfo.paddingLength 或其他单耗字段）
  - 按垫胶规格分别统计对应的成型机台数量（即消耗该垫胶的成型计划去重后的 CX_MACHINE_CODE），从排产参数 `CX_MACHINE_DEPTH_MAP` 中分别解析出每个垫胶规格对应的排产深度（即供应窗口，垫胶按此班次数检查库存是否满足成型需求）
    - 配置格式：`成型机台数1:计划班数1,成型机台数2:计划班数2`，如 `1:4,2:3,4:2`
    - 解析时按机台数匹配最近档位：若某规格的机台数在配置中无精确匹配，取小于等于该规格机台数的最大档位
    - **供应窗口超出成型计划范围**：若某规格的供应窗口班次数 > 成型计划已有的班次数（8个班），超出部分需按以下算法预估成型需求量。预估前需先加载月计划余量数据：
      - 数据源：com.zlt.aps.mp.api.domain.entity.MpMonthPlanMonitor
      - 表名：T_MP_MONTH_PLAN_MONITOR
      - 加载方式：使用 MpMonthPlanMonitorMapper.selectList
      - 加载条件：factoryCode = factoryCode参数, yearMonth = scheduleDate 对应的年月（YYYYMM）
      - 关键字段：

| 字段名 | 类型 | 备注 |
|--------|------|------|
| MATERIAL_CODE | varchar | 物料编码（外胎物料编码） |
| PRODUCT_TYPE_CODE | varchar | 产品品类 |
| LH_MARGIN | int | 硫化余量（条） |
| MONTH_PLAN_VERSION | varchar | 需求计划版本 |

      - 关联方式：通过垫胶施工清单获取外胎物料编码（materialCode）与 MpMonthPlanMonitor.materialCode 匹配
      - 预估算法：
      1. **计算垫胶月度剩余量**：`paddingRemaining = lhMargin × paddingLength`（硫化余量 × 单耗，换算为垫胶米数）
      2. **按最大班需求量预估**：取成型计划最后一天三个班中最大班需求量作为超出部分每个班的预估需求量，但累计预估值不得超过 `paddingRemaining`
  - 按垫胶代码和班次整理成型消耗量：`consumeQty[paddingCode][shiftIndex] = 该班次成型计划量 × 单耗`
- 3.3 关联垫胶施工清单与垫胶库存，计算初始库存
  - 有效库存量 = stockNum + modifyNum - badNum（早上6点库存快照）
  - **第1班接班库存 ≠ 有效库存**：有效库存为早上6:00快照，而第1班（中班）开班时间为14:00，中间8小时（早班6:00~14:00）的库存变化需按以下公式预估：
    ```
    第1班接班库存 = 有效库存 + T-1日早班垫胶计划量 - T日早班成型消耗量
    ```
    - **T-1日早班垫胶计划量**：从 T-1 日的 `T_DJ_SCHEDULE_RESULT` 表获取 `class3_plan_qty`（早班计划量），按垫胶代码汇总
    - **T日早班成型消耗量**：从 T 日的成型计划（CX）class1 计划量按单耗换算的垫胶消耗量
    - 若计算结果为负，则取 0（库存不能为负）
  - **新规格标记**：记录该垫胶代码在库存表中是否存在。若该垫胶代码在 `T_DJ_STOCK` 表中无任何记录（即步骤3.1中未查询到该垫胶代码的库存数据），则标记 `isNewSpec=true`，否则 `isNewSpec=false`。仅当库存表中完全不存在该垫胶代码时才视为新规格，仅库存量为0但已有历史记录的不算新规格。
  - 记录该垫胶规格对应的最早成型需求时间（取各班次中最早的）
  - 准备垫胶需求清单，包含所有有成型需求的垫胶规格（不在此步排除任何规格）
- 3.4 维护各规格的滚动库存状态（在步骤5排产过程中按班次更新）
  - 交班库存 = 接班库存 + 本班次生产量 - 本班次成型消耗量
  - 接班库存 = 上个班的交班库存，第1班接班库存按步骤3.3计算（不等同于有效库存）
  - 每个班次排产前，按当前接班库存检查是否满足供应窗口内的成型需求量
  - **损耗率处理说明**：已收尾规格的净需求在步骤5.1中按损耗率放大（`需求量 × (1 + 损耗率)`），确保排产时直接产出含损耗的合格量；未收尾规格的损耗率在步骤5.5最终输出时统一折算
## 步骤4：根据垫胶需求清单与需求量选择机台
- 4.1 加载垫胶机台数据
  - 数据源：com.zlt.aps.dj.api.domain.entity.DjMachineInfo
  - 表名：T_DJ_MACHINE_INFO
  - 加载方式：使用 DjMachineInfoMapper.selectList
  - 加载条件：factoryCode = factoryCode参数, status = 0（启用状态）
  - 关键字段：

| 字段名                | 类型      | 备注             |
| ------------------ | ------- | -------------- |
| FACTORY_CODE       | varchar | 工厂编码           |
| MACHINE_CODE       | varchar | 机台编号           |
| MACHINE_NAME       | varchar | 机台名称           |
| WIDTH_MIN          | decimal | 胶料最小宽度（米）      |
| WIDTH_MAX          | decimal | 胶料最大宽度（米）      |
| THICK_MIN          | decimal | 胶料最小厚度（米）      |
| THICK_MAX          | decimal | 胶料最大厚度（米）      |
| QUATA              | decimal | 生产定额（米/班）      |
| CLASS_SHIFT        | varchar | 班制，如：三班制、两班制   |
| OPEN_MACHINE_CLASS | varchar | 开机班次，如：中班、夜班   |
| STATUS             | char(1) | 机台状态：0-启用，1-禁用 |
- 4.2 加载定点机台数据
  - 数据源：com.zlt.aps.dj.api.domain.entity.DjSpecifyMachine
  - 表名：T_DJ_SPECIFY_MACHINE
  - 加载方式：使用 DjSpecifyMachineMapper.selectList
  - 加载条件：factoryCode = factoryCode参数, paddingCode in (垫胶需求清单的垫胶代码集合)
  - 关键字段：

| 字段名          | 类型      | 备注                 |
| ------------ | ------- | ------------------ |
| FACTORY_CODE | varchar | 工厂编码               |
| PADDING_CODE | varchar | 垫胶代码               |
| MACHINE_CODE | varchar | 机台编码               |
| LINE_TYPE    | varchar | 线路：0-生产线、1-备用线     |
| JOB_TYPE     | varchar | 作业类型：0-限制作业、1-不可作业 |
- 4.3 关联垫胶需求清单、定点机台数据、机台数据，将垫胶需求清单关联上生产的机台
  - 关联路径：垫胶需求清单.paddingCode → DjSpecifyMachine.paddingCode（匹配定点机台）→ DjSpecifyMachine.machineCode → DjMachineInfo.machineCode（获取机台详细信息）
  - 过滤条件：排除 DjSpecifyMachine.jobType = 1（不可作业）的定点关系；按 DjSpecifyMachine.lineType 区分生产线（优先）和备用线
  - 机台产能校验：DjMachineInfo.quata（定额）× 班次数量，判断机台是否有足够产能满足需求
  - **多机台负载分配策略**：同一垫胶规格关联多个机台时，按以下优先级分配生产量：
    1. **优先填满一个机台**：先按主生产线机台（lineType=0）分配，若该机台产能充足则由其独立完成全部需求
    2. **产能不足时拆分**：当主生产线机台产能不足（即该机台在可用班次内的总产能 < 需求总量）时，才将剩余需求分配到备用线机台（lineType=1）
    3. **多个备用线机台**：若备用线也有多个机台，按机台定额从高到低依次分配剩余产能

#### 机台班次产能结构

**机台可用班次判定**：
- DjMachineInfo.classShift 决定班制：`三班制`（夜班+早班+中班）、`两班制`（夜班+早班）
- DjMachineInfo.openMachineClass 决定开机班次，存储值为 ClassNumThreePlanEnums.classIndex：`"01"`=夜班、`"02"`=早班、`"03"`=中班
  - 如 `"01,02,03"` 表示夜班+早班+中班全部开机（三班制）
  - 如 `"01,02"` 表示夜班+早班开机（两班制）
  - 如 `"03"` 表示仅中班开机
- 机台在某班次是否可用 = openMachineClass 包含该班次对应的 ClassNumThreePlanEnums.classIndex

班次索引与ClassNumThreePlanEnums对照：

| 班次索引 | 班次名称 | ClassNumThreePlanEnums | 说明 |
|:-------:|:-------:|:--------------|:-----|
| 1 | 中班 | CLASS_DAY("03") | 垫胶第1班=当天中班 |
| 2 | 夜班 | CLASS_NIGHT("01") | |
| 3 | 早班 | CLASS_MORNING("02") | |
| 4 | 中班 | CLASS_DAY("03") | 次日中班 |
| 5 | 夜班 | CLASS_NIGHT("01") | 次日夜班 |
| 6 | 早班 | CLASS_MORNING("02") | 次日早班 |

**产能计算**：
- 机台可用产能基线 = DjMachineInfo.quata（米/班），即该机台每班可生产的定额米数
- 机台在某班次不可用时，该班次有效可用产能 = 0
- 机台在某班次的有效可用产能 = 机台可用产能基线 - 停机损失产量
  - 停机损失产量 = (检修计划停机时长 / 班次总时长8小时) × 机台定额
  - 检修计划数据来源：T_DJ_MACHINE_MAINTENANCE（垫胶机台维修计划）
- **台车总容量约束**：一个班次内所有机台的总排产量之和不能超过台车工装约束上限
  - `班次总产量上限 = (工装总数 - (有效库存 / 卷曲米数) × 整车率) × 台车容量`
  - 工装总数、整车率等参数来源于 DjParams 配置
  - **每班的实际可排产总量** = min(班次总产量上限, 该班次所有开机机台的有效可用产能之和)

### 5.1 按生产优先级排序，将规格安排到机台最早的可用班次上

#### 算法总览

```
// 预先计算机台每个班次的有效可用产能（含检修停机扣减）
capacityMatrix = calcEffectiveCapacity(machineList, shiftCount, maintenancePlan)

// 计算每班的台车工装约束上限（班次总产量上限）
shiftTrolleyLimit = calcShiftTrolleyLimit(effectiveStockMap, trolleyTotalNum, trolleyFullRate)

// 初始化各规格第1班接班库存 = 有效库存量（来自步骤3.1）
handoverInventory = initHandoverInventory(demandList, effectiveStockMap)

// 各垫胶规格的排产深度（供应窗口班次数），key=paddingCode, value=supplyDepth
paddingSupplyDepth = {}  // 来自 calcPaddingCxMachineCount + CX_MACHINE_DEPTH_MAP
for each paddingCode in demandList:
    paddingSupplyDepth[paddingCode] = getSupplyDepth(paddingCxMachineCount[paddingCode])

for shiftIndex = 1 to 6:                          // 遍历6个班次
    // 本班实际可用的产能上限 = min(班次总产量上限, 所有开机机台产能之和)
    shiftTotalCapacity = calcShiftTotalCapacity(capacityMatrix, shiftIndex, shiftTrolleyLimit)
    shiftRemainingCapacity = shiftTotalCapacity

    for each spec in demandList:
        specSupplyDepth = paddingSupplyDepth[spec.paddingCode]  // 该规格对应的排产深度
        // 该班次排产范围 = shiftIndex 到 shiftIndex + specSupplyDepth - 1 内的成型消耗量
        spec.incomingInventory = handoverInventory[spec.paddingCode]  // 本班接班库存
        // 检查接班库存是否满足供应窗口内的总成型消耗量
        demandInWindow = sum(consumeQty[spec.paddingCode][shiftIndex...shiftIndex+specSupplyDepth-1])
        // 已收尾规格：需求量需含损耗率，确保生产出足够的合格品
        if spec.isTailFinished:
            lossRate = getLossRate(spec.paddingCode, spec.machineCode)
            demandInWindow = demandInWindow × (1 + lossRate)
        if spec.incomingInventory >= demandInWindow:
            spec.needProduce = false                                  // 库存充足，本班不排产该规格
        else:
            spec.needProduce = true                                   // 库存不足，计算净需求并排产
            spec.netDemand = demandInWindow - spec.incomingInventory  // 本班需生产的净需求（已收尾规格已含损耗率）

    for each machineCode in activeMachines:         // 遍历所有机台
        if not isMachineAvailable(machineCode, shiftIndex):
            continue                                // 本班此机台不开机
        remainingCapacity = capacityMatrix[machineCode][shiftIndex] // 本班初始可用产能（已扣停机损失）
        // 机台剩余产能不能超过本班台车约束的剩余量
        remainingCapacity = min(remainingCapacity, shiftRemainingCapacity)
        lastSpecCode = getLastSpecOfPrevShift(machineCode, shiftIndex) // 上一班最后生产的规格
        // 只取本班 needProduce=true 的规格进行排产
        pendingSpecs = getSpecsByMachine(machineCode, demandList, shiftIndex)
        sortedSpecs = sortByPriority(pendingSpecs, machineCode, shiftIndex, lastSpecCode)
        for each spec in sortedSpecs:
            if not spec.needProduce or spec.netDemand <= 0:
                continue
            if remainingCapacity <= 0:
                break                               // 本班产能用完
            // 计算机台从上一规格切换到当前规格的产量损失
            switchLoss = calcSwitchLoss(machineCode, lastSpecCode, spec.paddingCode)
            produceQty = calcProduceQty(spec, remainingCapacity - switchLoss, shiftIndex)
            if produceQty <= 0:
                continue                            // 当前规格安排不下，继续下一规格
            recordSchedule(spec, shiftIndex, produceQty, switchLoss)
            spec.netDemand -= produceQty             // 扣减已排产量
            lastSpecCode = spec.paddingCode          // 更新当前规格为上一规格
            remainingCapacity -= (produceQty + switchLoss) // 扣减机台剩余产能
            shiftRemainingCapacity -= produceQty     // 扣减本班台车约束剩余量

    // 【新增】本班排产完毕后，计算各规格的交班库存
    for each spec in demandList:
        produceQty = getScheduledQty(spec, shiftIndex)               // 本班实际排产量
        consumeQtyThisShift = consumeQty[spec.paddingCode][shiftIndex] // 本班成型消耗量
        handoverInventory[spec.paddingCode] = spec.incomingInventory + produceQty - consumeQtyThisShift
```

#### 机台可用班次判定（isMachineAvailable）

```
输入：machineCode, shiftIndex
输出：boolean

// 根据机台班制+开机班次判断
1. 解析 DjMachineInfo.openMachineClass，存储的是 ClassNumThreePlanEnums.classIndex 值
   - 如 "01,02,03" 表示夜班+早班+中班全部开机（三班制）
   - 如 "01,02" 表示夜班+早班开机（两班制）
2. 确定当前班次索引 shiftIndex 对应的 ClassNumThreePlanEnums.classIndex：
   - shiftIndex=1(中班) → classIndex="03" (CLASS_DAY)
   - shiftIndex=2(夜班) → classIndex="01" (CLASS_NIGHT)
   - shiftIndex=3(早班) → classIndex="02" (CLASS_MORNING)
   - shiftIndex=4(中班) → classIndex="03" (CLASS_DAY)
   - shiftIndex=5(夜班) → classIndex="01" (CLASS_NIGHT)

3. 机台是否可用 = openMachineClass 包含该 classIndex
```

#### 优先级排序规则（sortByPriority）

按以下优先级逐级排序待排产规格列表（优先级高的排在前面）：

1. **本班库存有缺口的优先**：检查该规格在当前班次是否存在库存缺口。
   - 计算方式：该规格在成型计划中对应需求时间 ≤ 当前班次结束时间的班次需求量之和 > 当前有效库存
   - 有缺口的规格比无缺口的规格优先级高
   
2. **规格续作优先**：检查上一个班次该机台最后一个生产的规格是否还有剩余需求量，如果有则优先安排本班继续生产。
   - 使用 lastSpecInShift[(machineCode, shiftIndex-1)] 记录的规格代码
   - 上一个班=shiftIndex-1，如果shiftIndex=1则取前一天最后一个班的最后规格
   
3. **胶料相同且口型相同优先**：与上一个班次该机台最后生产的规格比较，胶料代码（glueCode）和口型板编码（mouthPlateCode）都相同的优先。

4. **胶料相同优先**：仅胶料代码相同的优先。

5. **口型相同优先**：仅口型板编码相同的优先。

6. **胶料组相同优先**：胶料组别相同的优先（从 DjGlueGroupOrder 表获取胶料组信息）。

7. **胶料序号升序**：按胶料序号（glueSeq）升序排列（从 DjGlueOrder 表获取）。

8. **库消比升序**：按库存与成型日消耗量的比值升序排列。
   - 库消比 = 当前有效库存 / 该规格在成型计划中日均消耗量
   - 比值越小说明库存越紧张，越需要优先生产

9. **垫胶编码升序**：按paddingCode字母/数字升序排列（兜底规则）。

#### 生产量计算（calcProduceQty）

根据规格的收尾状态和台车约束，计算本班可生产的量：

```
输入：spec（垫胶需求），remainingCapacity（本班剩余产能），shiftIndex
输出：produceQty（本班安排的生产量，单位：米）

// 规则A：已收尾规格（成型已全部收尾）→ 精确排产（含损耗率）
// 说明：已收尾规格的剩余需求（remainingDemand）已在步骤5.1中按损耗率放大，
// 此处直接按含损耗率的剩余需求排产，不要求台车整倍数
if spec.isTailFinished:
    produceQty = min(spec.remainingDemand, remainingCapacity)

// 规则B：未收尾规格 → 需为台车容量的整倍数
else:
    // 计算最大可生产的整台车数
    maxTrolleys = floor(remainingCapacity / spec.trolleyCapacity)
    // 计算剩余需求所需台车数
    needTrolleys = ceil(spec.remainingDemand / spec.trolleyCapacity)
    // 实际可生产的台车数
    actualTrolleys = min(maxTrolleys, needTrolleys)
    if actualTrolleys <= 0:
        // 连一台车都放不下，本班不生产此规格，留到下一班
        produceQty = 0
        // 继续下一个规格
    else:
        produceQty = actualTrolleys * spec.trolleyCapacity
        // 注意：如果剩余需求不足一台车但仍有需求，至少生产一台车
        if spec.remainingDemand > 0 and produceQty < spec.trolleyCapacity:
            if remainingCapacity >= spec.trolleyCapacity:
                produceQty = spec.trolleyCapacity
```

### 5.2 机台扣减消耗的产能

每为一个规格分配完生产量后，执行扣减：

```
// 扣减该规格的剩余需求
spec.remainingDemand = spec.remainingDemand - produceQty

// 扣减本班次该机台的剩余产能（含规格切换的产量损失）
remainingCapacity = remainingCapacity - produceQty - switchLoss

// 记录排产结果到DjScheduleResult对应班次字段
specSchedule.class{shiftIndex}PlanQty = produceQty
// 生产顺序按（机台，班次）独立编号，每个机台每个班次从1开始递增
shiftSeqMap[machineCode][shiftIndex]++
specSchedule.class{shiftIndex}Sequence = shiftSeqMap[machineCode][shiftIndex]

// 记录本班次该机台最后生产的规格（用于下一班的"规格续作"判断）
lastSpecInShift[(machineCode, shiftIndex)] = spec.paddingCode

// 如果本班该机台剩余产能 = 0，则本班该机台排产结束
if remainingCapacity <= 0:
    break  // 跳出本班该机台的规格循环，进入下一机台或下一班次
```

> 规格切换产量损失（switchLoss）：当一个班次内机台从生产规格A切换到生产规格B时，需要停机切换时间，这段时间本可生产的产量即为切换损失。
> 切换时间根据前后规格的胶料和口型比较，从排产参数获取：
> - 若当前是本班次安排的第一个规格（无上一规格），或上一规格与本规格编码相同（续做），则 switchLoss = 0
> - 胶料代码相同且口型板编码相同（即同一规格续做）：switchLoss = 0（已包含在上述续做情况中）
> - 胶料代码相同但口型板编码不同（仅切换口型）：switchLoss = (MOUTH_PLATE_SWITCH_TIME / 班次总时长) × 机台定额
> - 胶料代码不同（含口型也同时切换）：switchLoss = (GLUE_SWITCH_TIME / 班次总时长) × 机台定额
>
> 转换公式：switchLoss = (切换时长 / 8小时) × DjMachineInfo.quata

### 5.3 重复步骤5，终止条件判断

循环执行5.1~5.2，直到满足以下任一终止条件：

1. **所有6个班次全部排完**：shiftIndex从1遍历到6，所有机台在每个班次的产能都已分配完毕。
2. **所有垫胶需求均已排完**：所有垫胶规格的remainingDemand ≤ 0（即净需求量已全部安排到各机台班次上）。

满足任一条件即停止排产，进入步骤6（结果输出）。

### 5.4 特殊场景处理

#### 停产开产场景

每个工序有独立的工作日历（MdmWorkCalendar），成型（procCode=03）与垫胶（procCode=07）的停开产安排相互独立。通过各工序的 `DAY_FLAG`（日停开标志）和各班次 `ONE_SHIFT_FLAG`/`TWO_SHIFT_FLAG`/`THREE_SHIFT_FLAG` 判断。根据两个工序的停开组合，分以下场景处理：

- **场景一：成型停产，垫胶不停产**
  - 成型连续停产天数 < 排产参数 `SHUTDOWN_DAYS_THRESHOLD`（默认2天）：垫胶只需按需求量计算公式备足成型开产所需库存即可
  - 成型连续停产天数 ≥ 排产参数 `SHUTDOWN_DAYS_THRESHOLD`（默认2天）：垫胶需要收尾，精确排产，防止垫胶库存超期

- **场景二：垫胶停产，成型不停产**
  - 通常原因是垫胶库存充足。只需在停产前按需求量补够库存，确保成型在垫胶停产期间不断供即可

- **场景三：成型与垫胶同时停产**
  - 垫胶按成型收尾处理（isTailFinished标记），精确排产，避免产生过期废料

**开产策略**（连续停产天数 ≥ `SHUTDOWN_DAYS_THRESHOLD` 后开产，即该工序 DAY_FLAG 从 0 变为 1 的首个班次）：
1. 优先生产最早成型需求时间的规格
2. 当某规格库存达到安全水位线后，立即切换下一优先级规格（安全水位线从排产参数 `SAFETY_STOCK_LEVEL` 获取，表示库存可满足未来 N 个班次的成型需求量）
3. 所有规格均达安全水位后，恢复为正常优先级排序

#### 新规格/实验量试规格
- 新规格准备料：通过 `DjPaddingDemand.isNewSpec=true` 判定（步骤3.3中根据库存表是否存在该垫胶代码记录识别）。检测到新规格时，该规格需求的垫胶需提前2个班次下计划
- 实验量试规格：判定依据为 `MdmConstructionInfo.productionStage`，值为 `T`（量试阶段）或 `X`（试制阶段）时视为实验/量试规格。检测到实验/量试规格时，提前3个班次下计划

#### 放假停产收尾判断
- 若成型计划中该规格productionStatus=2（已收尾），则isTailFinished=true，排产时走精确排产规则
- 已收尾规格的净需求在步骤5.1中按损耗率放大（`需求量 × (1 + 损耗率)`），确保排产产出的合格量满足成型实际需求

### 5.5 排产结果输出

步骤5执行完成后，每个垫胶需求规格生成一条 DjScheduleResult 记录，填充以下关键字段：

| DjScheduleResult字段 | 填充方式 |
|---------------------|---------|
| factoryCode | 从步骤1传入 |
| batchNo | 自动生成，格式：`DJ + yyyyMMdd + 3位序号`。3位序号通过查询 `T_DJ_SCHEDULE_RESULT` 表获取当天已使用的最大批次号序号 +1 生成（如当天无记录则从 001 开始） |
| orderNo | 自动生成，格式：`batchNo + 4位序号`。每个 batchNo 批次内，从 001 开始连续编号 |
| scheduleDate | 从步骤1传入（排产日期） |
| machineCode | 从步骤4确定的机台编码 |
| paddingCode | 垫胶代码 |
| stockQty | 排程时使用的有效库存量（从 `T_DJ_STOCK` 加载的 `stockNum + modifyNum - badNum`） |
| glueCode | 胶料代码（从施工清单获取） |
| mouthPlateCode | 口型板编码（从施工清单获取） |
| class1PlanQty~class6PlanQty | 步骤5.2分配的6个班的计划量 |
| class1Sequence~class6Sequence | 步骤5.2分配的生产顺序 |
| tailFlag | 是否收尾任务：0-否，1-是 |
| releaseStatus | 发布状态：0-未发布，1-待发布 |

#### 排产结果转换为计划量

每个班的计划量计算完毕后，还需进行以下转换计算，作为最终保存结果：

```
// 损耗率处理（仅对未收尾规格执行，已收尾规格的需求量已在步骤5.1含损耗率计算）
for each shiftIndex in 1..6:
    planQty = specSchedule.class{shiftIndex}PlanQty
    if planQty > 0 and specSchedule.tailFlag != 1:
        // 含损耗率的最终计划量 = 计划量 × (1 + 损耗率)
        lossRate = getLossRate(specSchedule.paddingCode, specSchedule.machineCode)
        finalPlanQty = planQty × (1 + lossRate)
        specSchedule.class{shiftIndex}PlanQty = ceil(finalPlanQty)
```

#### 排产结果写入表

最终排产结果批量写入 `T_DJ_SCHEDULE_RESULT` 表，每条记录对应一个垫胶规格在一个机台上的6个班排产计划。写入前，先执行历史数据归档：

```
// 归档历史数据：将同一工厂+排产日的旧记录转移到日志表
// T_DJ_SCHEDULE_RESULT_LOG 继承自 DjScheduleResult，表结构与主表一致
oldRecords = select from T_DJ_SCHEDULE_RESULT
    where FACTORY_CODE = factoryCode
    and SCHEDULE_DATE = scheduleDate
if oldRecords is not empty:
    insert into T_DJ_SCHEDULE_RESULT_LOG select oldRecords  // 批量插入日志表
    delete from T_DJ_SCHEDULE_RESULT                          // 删除主表旧数据

// 批量写入新的排产结果
insert into T_DJ_SCHEDULE_RESULT (scheduleResultList)
```
