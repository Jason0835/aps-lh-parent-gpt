# 2026-08-21 工作日志

## 硫化日模具/机台数计算公共方法

### 背景
封装 `MpWeekRollAdjustEngine#getMouldByDay` 调用，在 aps-lh 中提供公共模具计算能力。

### 新建/修改文件
1. **新建** `APS-Modules/aps-lh/src/main/java/com/zlt/aps/lh/service/ILhDailyMouldCalcService.java`
   - 接口含4个方法 + `DailyMouldResult` 内部结果类
2. **新建** `APS-Modules/aps-lh/src/main/java/com/zlt/aps/lh/service/impl/LhDailyMouldCalcServiceImpl.java`
   - 实现：loadDailyCapacityLimitMap / loadMouldAdjustParamMap / getDailyMouldByDay / getDailyMouldByDate
3. **修改** `APS-Modules/aps-lh/src/main/java/com/zlt/aps/lh/context/LhScheduleContext.java`
   - 新增 `dailyCapacityLimitVoMap` (Map<Integer, MpDailyCapacityLimitVo>) 和 `mouldAdjustParamMap` (Map<String, Object>)

### 关键技术点
- `getMouldByDay` 返回日模具数，机台数 = 模具数 / 2
- `iDay` 为月内天序号(1~31)
- `FactoryMonthPlanProductionFinalResult` 通过 `BeanUtils.copyProperties` 转为 `FactoryMonthPlanFinalAdjustVo`
- `getFieldValueByFieldName` 来自 ruoyi `BaseEntity`（com.ruoyi.common.core.web.domain.BaseEntity），通过反射动态访问 day1~day31 字段
- aps-lh 参数体系(T_LH_PARAMS)与 getMouldByDay 所需排产参数体系(T_MP_FACTORY_PARAM)不同，需通过 `FactoryParamMapper` 额外加载 SYS0203003~SYS0203006
- `MpWeekRollAdjustEngine` 和 `MpAdjustDailyCapacityLimit` 无状态，直接 new
- `MpDailyCapacityLimitVo` 需设置 `openProductionFirstDay`(开产首日标识) 和 `dayProductionRate`(日产比例)
- pom 依赖：aps-lh 已依赖 aps-maindata、aps-mp-api、aps-engine-mp-core

### 第二轮：productStatus 区分 + 数据加载环节预计算
1. **DailyMouldResult** 新增 `productStatus` 字段 + `buildCacheKey()` 静态方法（key=materialCode|productStatus）
2. **ILhDailyMouldCalcService** 新增3个方法：
   - `loadDailyMouldSummary(context)` — 按排程日期(T日)预计算所有在产SKU模具数，存入 context.dailyMouldResultMap
   - `getMachineQty(context, materialCode, productStatus)` — 便捷查询机台数
   - `getDailyMouldResult(context, materialCode, productStatus)` — 查询完整结果
3. **LhScheduleContext** 新增 `dailyMouldResultMap` (Map<String, DailyMouldResult>)
4. **LhBaseDataServiceImpl.loadAllBaseData** 屏障同步后（loadEmbryoEndingFlagMap 之后）调用 `loadDailyMouldSummary`
   - 注入 `ILhDailyMouldCalcService`（@Resource）
   - 无 Spring 循环依赖（LhDailyMouldCalcServiceImpl 仅依赖 FactoryParamMapper）
5. 移除了 `loadMouldAdjustParamMap` 中手动追加的 `isDelete` 条件（框架自动处理逻辑删除）

### 第三轮：T~T+2 窗口预计算 + DailyMouldSummary 值对象
1. **loadDailyMouldSummary** 改为计算 T、T+1、T+2 三天逐日模具数/机台数；月计划 day1~day31 仅覆盖排程当月，跨月窗口日期跳过并 warn 日志
2. **新增 DailyMouldSummary** 值对象（ILhDailyMouldCalcService 内部类）：materialCode/productStatus/structureName + `dayMouldMap`（LinkedHashMap，key=日期字符串 yyyy-MM-dd，value=DailyMouldResult）
3. **DailyMouldResult** 新增 `date` 字段（对应窗口内具体日期）
4. **LhScheduleContext.dailyMouldResultMap** 类型改为 `Map<String, ILhDailyMouldCalcService.DailyMouldSummary>`
5. 查询方法调整：
   - `getMachineQty(context, mc, ps)` → T日机台数
   - `getMachineQty(context, mc, ps, date)` → 指定日期机台数
   - `getDailyMouldSummary(context, mc, ps)` → 窗口汇总（含逐日结果）
   - `getDailyMouldResult(context, mc, ps, date)` → 指定日期单日结果
6. 日期key统一 `yyyy-MM-dd` 字符串（`formatDateKey`），Date/LocalDate 转换走 `toLocalDate`
7. LhBaseDataServiceImpl 第5步注释同步更新为 T~T+2 窗口口径

### 第四轮：T~T+2 窗口支持跨月
1. `LhScheduleContext.dailyCapacityLimitVoMap` key 从月内天序号(1~31)改为日期字符串(yyyy-MM-dd)，跨月不冲突；`loadDailyCapacityLimitMap` 改为合并式（putAll 累积，可按年月多次调用）
2. `getDailyMouldByDay` 签名从 `Integer iDay` 改为 `Date date`（内部解析 iDay=dayOfMonth + dateKey）
3. `loadDailyMouldSummary` 跨月逻辑：
   - 窗口日期按年月分组，逐月调 `loadDailyCapacityLimitMap` 合并加载
   - 排程当月计划行复用 `context.getMonthPlanList()`；跨入月份用 `queryCrossMonthPlanList` 按 factoryCode+year+month+productionVersion 查 DB（与 LhBaseDataServiceImpl.queryMonthPlan 同口径，版本经 `resolveProductionVersionForMonth` 从 productionVersionByYearMonthMap 解析）
   - 以排程当月在产 SKU（materialCode|productStatus）为全集；跨入月无对应计划行时该日机台数记0（仍占窗口位）
4. 窗口天数复用 `LhScheduleConstant.STRUCTURE_ENDING_ALIGNMENT_WINDOW_DAYS = 3`（结构收尾对齐三天窗口同口径，[T,T+3) 即 T/T+1/T+2）
5. 注入 `FactoryMonthPlanProductionFinalResultMapper`（aps-lh 本地 mapper，com.zlt.aps.lh.mapper 包）
6. 新增私有方法：queryCrossMonthPlanList / resolveProductionVersionForMonth / buildMonthPlanIndex（key 重复保留首行）/ toLocalDate / formatDateKey（统一 DATE_KEY_FORMATTER）
7. 关键发现：版本加载范围 requiredMonthMap 覆盖到 earlyProductionLookupEndDate（排程窗口+提前生产观察天数），T+2 跨入月版本通常已在 productionVersionByYearMonthMap 中

### 第五轮：日期 key 从 String(yyyy-MM-dd) 重构为 LocalDate
1. 动因：Date 做 key 有时间分量陷阱（equals 比毫秒），String 类型安全弱；LocalDate 为天粒度值对象，最稳
2. `DailyMouldSummary.dayMouldMap` → `Map<LocalDate, DailyMouldResult>`（putDayMould/getDayMould/getDayMachineQty/getDayMouldMap 全部 LocalDate 签名）
3. `DailyMouldResult.date` → `LocalDate`
4. `LhScheduleContext.dailyCapacityLimitVoMap` → `Map<LocalDate, MpDailyCapacityLimitVo>`（与 dayMouldMap 口径统一）
5. `LhDailyMouldCalcServiceImpl`：删除 DATE_KEY_FORMATTER/formatDateKey；新增私有 `getDailyMouldByLocalDate`（Date 版公共方法委托它）；对外查询方法（getMachineQty/getDailyMouldResult 的 Date 参数）内部 `toLocalDate` 归一化后查 key，调用方传带时间的 Date 也不会踩坑

### 第六轮：跨月月计划复用 monthPlanByMaterialMonthMap + 代码精简
1. 关键发现：`LhBaseDataServiceImpl.loadMonthPlan`（L1325-1358）已按 `requiredMonthMap`（覆盖排程窗口+提前生产观察天数，含 T+2 跨入月）批量加载跨月月计划，且 `MonthPlanDateResolver.buildMaterialMonthPlanMap` 已构建好 `context.monthPlanByMaterialMonthMap`（key=`materialCode_productStatus_year_month`，putIfAbsent 去重）——自写查库完全冗余
2. 删除3个冗余私有方法：queryCrossMonthPlanList / resolveProductionVersionForMonth / buildMonthPlanIndex；删除 `FactoryMonthPlanProductionFinalResultMapper` 注入
3. `loadDailyMouldSummary` 简化：当月+跨月统一查 `monthPlanByMaterialMonthMap`（key 用 `MonthPlanDateResolver.buildMaterialStatusKey` + `buildMaterialMonthKey` 构建，注意与 buildCacheKey 的 key 体系不同）；查不到该月该SKU计划行时记0
4. 顺手精简：loadDailyCapacityLimitMap 复用 toLocalDate 消除重复转换、开产首日判断合并为单行布尔表达式；loadMouldAdjustParamMap 删手动 isDelete 条件（AGENTS.md 强制规范）
